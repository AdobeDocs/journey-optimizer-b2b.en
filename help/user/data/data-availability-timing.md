# Data availability and sync timing {#data-availability}

Use this topic to understand how quickly data changes appear in your [!DNL Adobe Journey Optimizer B2B Edition] journeys and which timelines are normal. Knowing the expected timing helps you design journeys accordingly and recognize when a delay is expected behavior.

## Expected wait times

| Data type | Typical availability |
| --- | --- |
| [Audience membership](#daily-refresh) | Up to 24 hours (daily cycle) |
| [Account and person relationship changes](#daily-refresh) | Up to 24 hours (daily cycle) |
| [Data from [!DNL Experience Platform] to [!DNL Journey Optimizer B2B Edition]](#platform-sync) | Up to 30 minutes (near real time) |
| [Data from [!DNL Journey Optimizer B2B Edition] to [!DNL Experience Platform]](#platform-sync) | Up to four hours (micro-batches) |
| [Activity events, such as clicks and opens](#activity-and-actions) | Up to four hours |
| [[!DNL Marketo Engage] list add or remove](#activity-and-actions) | Within 30 minutes (near real time) |
| [Events generated by Journey Optimizer B2B Edition](#activity-and-actions) | Usable in batch audiences only |
| [LinkedIn audience population](#linkedin-timing) | Same day to 36-40 hours (worst case) |

## Audience and relationship data {#daily-refresh}

[!DNL Journey Optimizer B2B Edition] evaluates account and person audience membership once per day, triggered by a batch job scheduler. As a result:

* Accounts or people who newly qualify for an audience become eligible to enter a journey within 24 hours of qualifying.
* Changes to audience criteria take effect in the next daily evaluation cycle.
* If an account qualified for an audience today but has not entered the journey yet, wait until the next daily cycle completes before investigating.
* When a person's account association changes, for example when a contact moves to a different account, the relationship update propagates within 24 hours through the daily sync cycle. Journeys that depend on account membership reflect the updated relationship after the next daily cycle. No action is needed.

>[!TIP]
>
>Design journeys with the understanding that audience membership is refreshed daily, not in real time. If you need near-real-time responses, use [event-based triggers](../journeys/listen-for-event-nodes.md) instead of audience-based entry.

## Data sync with [!DNL Experience Platform] {#platform-sync}

[!DNL Experience Platform] is the primary data store for accounts, people, and opportunities, and [!DNL Journey Optimizer B2B Edition] owns journeys, buying groups, and buying group roles. [Learn more about the architecture](../about-journey-optimizer-b2b-edition.md#high-level-architecture). 

Data moves between the two systems in each direction at a different pace:

* **[!DNL Experience Platform] to [!DNL Journey Optimizer B2B Edition]** - Data syncs in near real time and can take up to 30 minutes.
* **[!DNL Journey Optimizer B2B Edition] to [!DNL Experience Platform]** - Data syncs in micro-batches and can take up to 4 hours.

## Activity events and journey actions {#activity-and-actions}

Timing for activity data and journey actions depends on how the data moves between systems:

* **Activity data** - Person activity records, such as email opens, link clicks, and form fills, can take approximately four hours to appear in [!DNL Journey Optimizer B2B Edition]. This timing applies to batch activity data; [!DNL Experience Platform] Experience Event triggers use streaming data and can react in near real time.
* **[!DNL Marketo Engage] actions** - Journey actions that call [!DNL Marketo Engage] are near real time because they are API calls. For example, when a journey step adds or removes a person from a [!DNL Marketo] list, the action typically completes within 30 minutes. [Learn more about journey actions](../journeys/action-nodes.md).
* **Actions that go through [!DNL Experience Platform]** - Any action that returns to [!DNL Experience Platform] first is batched, so it is subject to batch timing rather than near-real-time timing.
* **Events generated by [!DNL Journey Optimizer B2B Edition]** - Events that [!DNL Journey Optimizer B2B Edition] generates in [!DNL Experience Platform] can only be used in batch audiences.

## [!DNL LinkedIn] audience destinations {#linkedin-timing}

If your journey includes a [!DNL LinkedIn] destination action, expect the following timeline after you publish the journey.

| Scenario | Expected wait |
| --- | --- |
| Accounts were already in the audience when the journey was published | Same day, if processing completes before midnight local time |
| Accounts arrived after the journey was published | Up to 24 hours |
| Accounts arrived after the first daily sync window | Up to 36-40 hours |

[!DNL LinkedIn] audience counts might not update immediately. This lag is an expected delay while [!DNL Experience Platform] processes and delivers the audience file to [!DNL LinkedIn]. If the audience count is still 0 after 48 hours, investigate. [Learn more about LinkedIn Account Matched Audiences](./linkedin-account-matched-audiences.md).
